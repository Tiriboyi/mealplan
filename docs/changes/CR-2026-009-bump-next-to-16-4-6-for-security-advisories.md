# CR-2026-009: Bump next to 16.4.6 for security advisories

RFC: [RFC-2026-009](../rfc/RFC-2026-009-bump-next-to-16-4-6-for-security-advisories.md) · Spec: none · Ticket: none · Analysis: none
Date: 2026-11-18

## Summary
Upgraded `next` from 16.4.2 to 16.4.6 (patch) to fix two moderate advisories reported by `npm audit`: GHSA-mfr8-8qww-v76h and GHSA-vc7v-qv4w-wrv8 (`use cache` data leaking across root params, range 16.2.0–16.4.4). Also set `experimental.agentUpgrade: "security"` in `next.config.ts`, so Next's upgrade reminders follow the security-only policy. Only `package.json`, `package-lock.json` and `next.config.ts` changed. No application code changed.

## Known limitations & follow-ups
- The smoke test was HTTP-only (status codes). Pages were not checked in a browser, and `/api/deals` was not called with real retailers.
- `npm run build` fails with "Cannot read properties of null (reading 'useContext')" on `/_global-error` when the shell has `NODE_ENV=development` set. This is an environment issue, not caused by this change: the build passes with `NODE_ENV` unset. Unset it before building.
- `npm run typecheck` in a fresh checkout fails on the logo image imports until `next-env.d.ts` exists (it is gitignored and generated by `next dev`/`next build`). This was already the case before this change.
- The generated "Files changed" list also includes `skills-lock.json` and RFC-2026-008, because `main` is ahead of `origin/main` by the RFC-2026-008 approval commit. They are not part of this change.
