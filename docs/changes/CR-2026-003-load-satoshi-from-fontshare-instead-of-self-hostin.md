# CR-2026-003: Load Satoshi from Fontshare instead of self-hosting it

RFC: [RFC-2026-003](../rfc/RFC-2026-003-load-satoshi-from-fontshare-instead-of-self-hostin.md) · Spec: none · Ticket: none · Analysis: none
Date: 2026-10-23

## Summary
Records the pre-devrailsv2 typography change (`acad3e6`: Instrument Serif headings, Satoshi body text, heading restyle) and fixes its licence problem. The self-hosted `Satoshi-Variable.woff2` and its licence file are removed, because the ITF Free Font License forbids distributing the font through a public repository. Satoshi now loads from Fontshare's CSS API (React 19 stylesheet link plus preconnects in `layout.tsx`), with a system font stack as fallback in `globals.css`.

## Known limitations & follow-ups
- **Build needs RFC-2026-002.** This branch pins `next@16.4.0`, and Next now refuses to build a version with known vulnerabilities (`SecurityFatalError`). AC-4's build was run with 16.4.2 installed temporarily (`npm install --no-save`), then `npm ci` restored the lockfile. PR #2 will only build in CI once the RFC-2026-002 bump is in it.
- **The outage was simulated, not real.** AC-3 removed the stylesheet in the page rather than blocking `*.fontshare.com` at network level. The fallback relies on standard CSS font-stack behaviour.
- **The font is still in git history:** in `acad3e6` and in GitHub's PR #2 refs. Purging it needs a history rewrite and force-push on the PR branch, and possibly GitHub support. That is the requester's decision (RFC Dependencies And Open Decisions).
- **Privacy:** each first visit now sends the visitor's IP address to Fontshare (Indian Type Foundry). The RFC marks this `Unclear`, for the requester to decide whether a notice is needed.
