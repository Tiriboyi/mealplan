# CR-2026-004: Record the SQLite promotions cache

RFC: [RFC-2026-004](../rfc/RFC-2026-004-record-the-sqlite-promotions-cache.md) · Spec: none · Ticket: none · Analysis: none

## Summary
Records the pre-devrailsv2 SQLite promotions cache (`79081ad`: `DealStore` on `node:sqlite`, full download plus changes-feed sync in `prijsprofeet.ts`, `MEALPLAN_DB`, README). Adds tests for the sync rules, which had none, and records the storage decision in ADR-0002. No production code changed.

## Known limitations & follow-ups
- **No red phase.** These tests record existing behaviour, so they passed on the first run, as the RFC predicted. To show they can fail, three temporary mutations of `prijsprofeet.ts` were each caught by their target test, and the file was then restored unchanged: throttle off (AC-6), 410 ignored (AC-8), and no shared sync (AC-10).
- **Not checked live against PrijsProfeet:** the tests stub `fetch`. The cache was exercised live earlier on 2026-10-23, when `/api/deals` returned 2,263 promotions for 6 retailers on another branch.
- **Untested paths:** the 429 retry/backoff in `get()` (it sleeps up to 30 s), and a failing first download with no local copy (the error reaches the page).
- **ADR numbering:** ADR-0002 is used because ADR-0001 (component tests) lives on the RFC-2026-001 branch. Both ADRs are still "Proposed" for the requester to accept.
- **Deployment:** the cache needs a writable, persistent disk (see ADR-0002).
