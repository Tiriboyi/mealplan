# CR-2026-005: Dinner options from the shopping list

RFC: [RFC-2026-005](../rfc/RFC-2026-005-dinner-options-from-the-shopping-list.md) · Spec: none · Ticket: GH#6 · Analysis: [analysis](../../docs/analysis/TICKET-gh-6.md)
Date: 2026-10-27

## Summary
Every day on the week view now shows up to two "Or make:" dinners that the week's shopping list already covers, or "No alternative dinner possible with this week's shopping". The new pure function `dinnerOptions()` in `src/lib/planner.ts` works them out from the realised plan without touching it, so the list, totals, budget planner, sadza rule and swap list are unchanged. Tapping an option opens its recipe sheet with ingredients tagged by their status on the list, and "Cook it instead" swaps it in for that day.

## Known limitations & follow-ups
- **Little variety across days.** The shopping list belongs to the whole week, so the set of makeable recipes is the same for every day; ranking only changes the order. In the checked week every day showed the same two recipes. A follow-up could spread different options across days.
- **Coverage is by ingredient, not quantity** (requester decision): cooking an option can use up groceries meant for a planned dinner.
- **AC-15 is unit-tested only** through `alternatives()`. The "Cook it instead on" footer from the recipes page has no component test; its code path is unchanged.
- **The component tests stub `HTMLDialogElement.showModal`** (jsdom has none) to set `open`. This was changed after the red commit; no assertion changed.
- **Manual check still open** at phone width (≤ 400 px) and in light mode.
